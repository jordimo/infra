# Dev diary — 2026-05-20

Two unrelated drivers landed on infra today: a 5-second dev-loop perf bug (rooted in `.local` mDNS handling) that turned into a TLD migration across all projects, and an external vulnerability scan that needed Traefik + base-image SHA bumps.

---

## Track 1 — `.local → .localhost` migration

### Trigger

Librarian's silent-SSO flow was taking ~5 seconds per request to `https://thehub.local/api/auth/sso/issue-token`. Added timing markers in TheHub's auth handler — endpoint returns in 3 ms. The 5 seconds was DNS:

```
curl -w "dns=%{time_namelookup}s" https://thehub.local
dns=5.004704s connect=5.004900s tls=5.011517s total=5.016280s
```

macOS resolves `.local` TLDs through mDNS/Bonjour *before* consulting `/etc/hosts`, and waits its full 5-second timeout before falling back. Every browser/curl request to any `*.local` hostname pays this.

### What got done

Picked `.localhost` over `.test`, `.dev`, `nip.io`, etc. — RFC 6761 reserves it, macOS resolves `*.localhost` natively to 127.0.0.1 without mDNS, and modern browsers treat it as a potentially-trustworthy origin.

Migration plan saved at `docs/migrations/2026-05-20-local-to-localhost.md`. Shipped via 5 per-repo PRs:

- **infra PR #3 merged at `628b985`** — cert regen (mkcert one-liner for all 8 projects), Traefik dynamic config (gitignored, local only), `docker-compose.yml`, `init-project.sh`, `start.sh`, and the migration plan doc
- jordimo/TheHub#36, jordimo/Marie#49, jordimo/thecollective-web#1, jordimo/lostriver-web#1 — per-app config (env vars, vite config, Traefik labels, test fixtures)

The cert layer was the simplification we hoped for: same `mkcert` CA, same filenames, so Traefik picked up new SANs on the next file-watch reload — no Keychain re-trust needed.

```bash
cd ~/Dev/infra/certs
for name in analytics betty infra lostriver marie neo4j thecollective thehub; do
  mkcert -cert-file "${name}.pem" -key-file "${name}-key.pem" \
    "${name}.localhost" "*.${name}.localhost"
done
```

### Performance result

| Endpoint | Before | After | Speedup |
|---|---|---|---|
| `mail.localhost` | 5,026 ms | 13 ms | 386× |
| `langfuse.localhost` | 5,026 ms | 10 ms | 502× |
| `thehub.localhost/api/auth/sso/issue-token` | 5,030 ms | 23 ms | 216× |

### Local-only librarian cert fix

`.local`-era infra didn't have a `librarian.pem` (Librarian wasn't running through Traefik until L2b). After the TLD migration Chrome started warning `ERR_CERT_COMMON_NAME_INVALID` on `librarian.localhost` because Traefik was serving the default `infra.pem` for unmatched hosts. Generated `librarian.pem` + appended an entry to `dynamic/tls.yml`. Both are gitignored — fix is per-machine.

## Track 2 — Vuln scan response

External scan against an older deployment of Marie on a different server flagged ~80 high-severity CVEs. Triaged into infra-side (Traefik + shared base images) vs app-side (Marie images).

### Traefik auth-bypass — infra PR #4

**PR #4 merged at `042d6d0`.** `traefik:v3.6` → `traefik:v3.6.14`. Closes three known-exploit auth-bypass CVEs:

- CVE-2026-35051 ForwardAuth bypass when `trustForwardHeader=false`
- CVE-2026-39858 forwarded-header alias bypass (`X_Forwarded_Proto` underscore vs dash)
- CVE-2026-40912 StripPrefixRegex + ForwardAuth bypass via dot-segment normalization

All fixed in 3.6.14. SHA-pinned. Verified locally — Traefik starts cleanly, `mail.localhost` 200 in 12 ms post-bump.

### Base image SHA bumps — infra PR #5

**PR #5 merged at `f04d7f8`.** Refreshes SHA pins for the three third-party services to current upstream digests:

| Service | Old SHA | New SHA | Closes |
|---|---|---|---|
| pgvector/pgvector:pg16 | `7d400e34…` | `00ba258a…` | OpenSSL 3.0.18 → 3.0.20 (5 CMS/DANE null derefs incl. Critical CVE-2026-31789), glibc 2.36-deb12u13 → -deb12u14 (3 known-exploit CVEs), libcap2 TOCTOU privesc, libxml2 updates, dpkg fixes |
| redis:7-alpine | `8b81dd37…` | `6ab0b6e7…` | libssl3/libcrypto3 3.3.6 → 3.3.7, musl 1.2.5-r9 → -r11 (qsort stack corruption) |
| docker.umami.is/…/umami | `28f263fe…` | `e3f80c06…` | libssl3 3.5.4 → 3.5.6 (Critical CVE-2026-31789), nghttp2 1.68.0 → 1.68.1, npm transitives |

All three verified healthy locally after the swap.

### Decisions made

- **`.localhost`, not `.test` or `.dev`.** Already covered in TheHub diary — `.localhost` resolves natively on macOS, no `/etc/hosts` entries required for new projects.
- **Bump Traefik 3.6.14, not 3.7.** All three CVEs fixed in 3.6.14; minor-version-stable bump is safer than crossing the 3.6→3.7 boundary.
- **SHA-pinned digests, not floating tags.** Same pattern as Traefik — gives a stable, reproducible artifact while still allowing intentional bumps via PR.
- **Don't restore the stashed `umami: init: true` change locally.** That was a local-only WIP for the host machine; not infra-shared.
