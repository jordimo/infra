## Session 1 — restart policy: unless-stopped → always

### What we worked on

Discovered a cascading failure on zora: postgres exited 0 after a manual reboot, didn't come back, took thehub-api into a crashloop. Root-caused the restart-policy semantics and updated all infra services.

### What got done

- Flipped `restart: unless-stopped` → `restart: always` for all 7 services in `docker-compose.yml`: traefik, postgres, redis, umami, vaultwarden, mailpit, neo4j (commit `b4df686`).
- Pulled + `docker compose up -d` on zora; force-recreated vaultwarden separately (it didn't get picked up by the first `up -d` since nothing else changed for it).
- Verified all services on zora now report `RestartPolicy: always`.

### Decisions made

- **`always` over `unless-stopped`.** `unless-stopped` skips restart when Docker decides the container "stopped on purpose" — including some clean exit-0 paths during boot ordering. That's exactly how postgres got stranded after zora's reboot at 2026-05-02 20:57 UTC. `always` retries unconditionally.
- **Trade-off accepted: local dev now also runs `always`.** Same compose file is used both locally (with `COMPOSE_PROFILES=local`) and on zora. Local impact: `docker stop <svc>` no longer keeps a service stopped — use `docker compose down` instead. Worth it to make prod reboots safe; can revisit with a profile-specific override file if it bites.

### Open threads

1. **Auto-reboot policy.** zora's `/etc/apt/apt.conf.d/50unattended-upgrades` has `Automatic-Reboot` commented out. Today's kernel (`linux-image-virtual` 6.8.0-90 → 6.8.0-110) was installed at 06:43 UTC and sat unused until we manually rebooted at 20:57. Decide: enable scheduled auto-reboot (e.g. `Automatic-Reboot-Time "03:00"`) or keep it manual. With `restart: always` in place now, an auto-reboot wouldn't strand services.
